PHẢN XẠ 1 GIÂY

3. MẸO PHẢN XẠ "1 GIÂY" (Liếc 1 từ trên Đề → Khóa 1 từ dưới Đáp Án)

A. Custom Tag & Phương thức vòng đời

  • 🔑 Thấy đề có doStartTag → Tìm ngay đáp án có EVAL_BODY_INCLUDE (hoặc SKIP_BODY).
  • 🔑 Thấy đề có doEndTag → Tìm ngay đáp án có EVAL_PAGE (hoặc SKIP_PAGE).
💡 Câu thần chú: "Start thì Body, End thì Page".

B. JDBC (Database)

  • 🔑 Đề có chữ stored procedures → Chọn ngay CallableStatement (Câu #334).
  • 🔑 Đề có PreparedStatement (ưu điểm/lợi ích) → Chọn đáp án có chữ precompiled hoặc parameter (?) hoặc Both A and B.
  • 🔑 Đề hỏi phương thức trả về ResultSet → executeQuery().
  • 🔑 Đề hỏi phương thức trả về số dòng dạng số nguyên int → executeUpdate().

C. JSP Scope & Đối tượng ngầm định (Implicit Objects)

  • 🔑 Đề hỏi is NOT a scope → Chọn ngay response (hoặc out). (Nhớ: chỉ có đúng 4 scope: page, request, session, application).
  • 🔑 Đề hỏi default scope của <jsp:useBean> → Chọn ngay page.
  • 🔑 Đề hỏi đối tượng ngầm định chỉ dùng được khi isErrorPage="true" → Chọn ngay exception.

D. Thư mục WAR & Cấu hình web.xml

  • 🔑 Thấy WEB-INF/lib → Chứa file thư viện .jar.
  • 🔑 Thấy WEB-INF/classes → Chứa file mã nguồn biên dịch .class (Servlets).
  • 🔑 Đề hỏi tham số chung cho toàn bộ ứng dụng (shared by all / entire web app) → Chọn ServletContext / thẻ <context-param>.
  • 🔑 Đề hỏi cấu hình riêng cho 1 Servlet duy nhất (single servlet) → Chọn ServletConfig / thẻ <init-param>.

E. Kiến trúc MVC & HTTP Method

  • 🔑 Đề hỏi NOT a component of MVC → Chọn ngay Database (hoặc Service Layer).
  • 🔑 Đề hỏi NOT an HTTP method → Chọn ngay UPDATE (vì UPDATE là câu lệnh của SQL!).
  • 🔑 Phân vai MVC: Controller = Servlet, View = JSP, Model = JavaBean / POJO / DAO.

F. Phân biệt Forward vs SendRedirect

  • 🔑 <jsp:forward> / RequestDispatcher.forward(): Chuyển tiếp bên trong Server, giữ nguyên URL trên thanh địa chỉ, chỉ tốn 1 request, giữ nguyên dữ liệu trong request scope.
  • 🔑 response.sendRedirect(): Chuyển hướng phía Client (trình duyệt gửi request thứ 2 mới hoàn toàn), đổi URL trên thanh địa chỉ, mã trạng thái là SC_MOVED_TEMPORARILY (302).

PHẢN XẠ 1 GIÂY

4. BẢNG TRA CỨU PHẢN XẠ "1 GIÂY" THEO 8 CHUYÊN ĐỀ (Liếc từ khóa Đề → Chốt ngay Đáp án)

A. Kỹ thuật White-box, Coverage & Phân loại

  • 🔑 NOT a black box testing technique → Decision testing (#28 - vì là White-box; đừng nhầm Decision tables!).
  • 🔑 NOT a White box technique → Boundary value analysis (#36) | Không thuộc White-box BS7925-II → Random testing (#125).
  • 🔑 odd one out giữa Glass/Clear/Transparent/Structural/White box → Black box testing (#76).
  • 🔑 Gồm cả Black-box và White-box (#54: Gray Box & Hybrid) → Both of (i) and (ii).
  • 🔑 not mimic real world situations → (ii) Structural Testing (#40) | Tên khác của White-box → Structural Testing (#160) | Đặc trưng White-box (#205) → i, ii are true.
  • 🔑 Cyclomatic Complexity thuộc White box (#108), công thức L - N + 2P (#216), phức tạp cao thì Difficult to test (#105).
  • 🔑 Code Coverage đo Test Effectiveness (#233); Coverage measurement là partial measure of test thoroughness (#319); Decision coverage đảm bảo thực thi mọi nhánh tại điểm quyết định (#310).

B. Kỹ thuật Black-box, Experience-based & Exploratory

  • 🔑 Specification-based đánh giá hành vi từ góc nhìn bên ngoài: external perspective (#240); mô hình không dùng cho functional testing: Plain language specification model (#104).
  • 🔑 Equivalence partitioning: mỗi phân vùng chỉ lấy 1 giá trị làm test case (#261), chia valid/invalid partitions (#311), phủ cả input & output (#56), áp dụng ở all levels of testing (#324).
  • 🔑 Boundary value testing: kiểm tra on, below and above the edges (#361).
  • 🔑 different combinations of inputs → Decision table testing (#90) | changes in state → State transition testing (#252).
  • 🔑 Use case testing → Business scenarios (#138), lỗi process flows & tương tác thành phần (#186: i, iii; #239; #351).
  • 🔑 skills, intuition, experience / Error guessing → Experience-based (#92, #96, #340).
